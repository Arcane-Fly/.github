# Contributing

Start with the repository's README and any repository-specific contribution guide. Those instructions take precedence over these organization defaults.

For a proposed change:

1. Work on a branch and open a pull request against the repository's intended target branch.
2. Keep the change focused and sign commits with your configured Git identity.
3. Explain the purpose and include the checks or evidence that show the change works. For a visible workflow, describe the interaction you exercised and whether saved state persisted after reopening or reloading, where applicable.
4. Keep secrets, customer information, and other private material out of commits, issues, and pull requests.

Use the [private security reporting route](SECURITY.md) for suspected vulnerabilities. For other questions, see [support](SUPPORT.md).
